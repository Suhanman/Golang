## Go 루틴이란 무엇인가요?

Go 루틴은 Go 런타임에  의해 관리되는 경량 실행단위 입니다.
OS 스레드와 비슷하게 동작하지만 운영체제가 아닌 Go 런타임에서 실행된다.  
주요특징은 다음과 같다

1. 매우 가벼운 리소스 (경량성)    
일반적인 OS 스레드가 1~2MB의 메모리를 처음부터 고정된 스택 메모리로 할당받는다면 고루티은 2kb의 아주 작은 스택 메모리만 사용합니다.
필요에 따라 런타임이 스택 크기를 동적으로 늘릭거나 줄이므로 한번에 수만개에서 수십만개의 고루틴을 동시에 생성해도 시스템에 큰 무리가 가지 않습니다.


2. 적은 컨텍스트 스위칭의 비용  
OS 스레드 간의 작업 전환은 운영체제 커널의 개입이 필요하며 비용이 크다.
하지만 고루틴은 GO 런터임 내부의 M:N 스케쥴러를 통하여 관리됩니다.
즉 M개의 고루틴을 N개의 OS 스레드에 적절히 분배하여 실행하기 때문에 커널 레벨의 컨텍스트 스위칭이 최소화되어 속도가 매우빠릅니다.


3. 직관적이고 간단한 사용법  


4. 채널을 통한 안전한 통신  
여러 스레드가 동시에 실행될 때 가장 어려운 것은 데이터 동기화(Lock 관리를 통한 공유 메모리의 접근)이다.
Go 언어는 이를 해결하기 위하여 채널이라는 파이프라인의 구조를 제공한다. 공유메모리를 통해 통신하는 것이 아닌 통신을 위해 메모리를 공유하라는 철학.


5. GPM 모델이란?  
G : 고루틴 그자체. 실행해야 할 GO 함수와 코드, 현재 고루틴의 상태, 스택 메모리와 포인터, PC 등의 메타데이터를 가지고 있는 논리적 작업의 단위.  
M : 머신. 운영체제의 커널 스레드를 의미. 실제 CPU 코어 위에서 코드를 실행하는 주체.  
P : 논리적 프로세서. G와 M 사이에서 작업을 조율 하는 역할. M이 G를 실행하기 위해서는 반드시 이 P를 획득하여야한다. 각 P는 실행대기중인 고루틴들을 보관하는 로컬 큐를 독자적 관리한다. 활성화된 머신의 CPU 코어수만큼 생성된다.  

6. GPM 모델 핵심 동작원리

- 실행 흐름 (M -> P -> G) : 스레드는 논리 프로세서를 항당받고, P의 로컬 큐에 들어있는 고루틴들을 순차적으로 꺼내어서 실행
- 작업 훔치기 : 특정 P의 로컬 큐에 할당된 작업이 다 끝나서 비었다면? 그 P는 놀지 않고 다른 P의 로컬 큐나 글로벌 큐에서 대기중인 G의 일부를 훔쳐옴. 이를 통하여 멀티 코어환경에서 모든 CPU가 쉬지 않고 고르게 일하도록 부하분산.
- Handoff: 고루틴 내부에서 파일 I/O나 네트워크 통신같은 시스템 콜을 호출하여 커널 스레드 자체가 블로킹에 빠지는 경우 생김. 이때 고 런타임은 해당 M에 연결된 P를 즉시 떼어내고 대기중인 다른 M에 넘겨준다.
덕분에 특정 스레드가 멈추더라도 해당 P의 큐에 대기중이던 다른 고루틴들은 지연 없이 계속 실행될 수 가 있다.
